# AuditAI

AuditAI is a no-login web app that helps startup teams estimate and prioritize savings on their AI tool stack.

The core recommendations are generated by a deterministic, rule-based audit engine (no login required). Optionally, the app also generates a short “executive summary” using an LLM provider (OpenAI or Anthropic). Email/lead capture happens after users generate a shareable report.

---

## Project Overview

### What users do

1. Go to `**/audit**` and enter:
  - team size, primary use case, currency
  - a list of tools with plan type, monthly spend, and seat counts
2. Click **Generate audit**
3. View deterministic recommendations + totals on `**/results`**
4. Persist a shareable report URL (after inputs are persisted)
5. Optionally submit contact information after generating a report.

### What the app calculates

Deterministic recommendations include:

- overkill plan detection (suggest downgrades when a team is below a plan’s intended minimum)
- cost-per-seat sanity checks (unused seats and unusually high effective cost/seat)
- redundant assistant detection (redundant overlapping assistants; removes the most expensive one deterministically)
- credit/discount opportunity when total spend is above a threshold
- “no change recommended” when nothing materially improves

### AI summary behavior (optional)

The AI summary is intentionally isolated:

- The deterministic report (recommendations + numeric savings) is computed locally via pure rules.
- The executive summary is generated by calling `**POST /api/summary**`.
- If the AI call is unavailable (no API key, provider error, empty output), the app falls back to a deterministic, rules-derived summary.

## Features

### Deterministic audit (first-class)

- Deterministic rule engine producing:
  - numeric monthly and annual savings totals
  - per-tool recommendations with confidence, severity, and reasons
- Deterministic tie-breaking and de-duping to avoid “random” outputs

### Executive summary (LLM optional)

- Provider-selectable backend route:
  - `**POST /api/summary**` (default provider is OpenAI; Anthropic supported in code)
- Prompt constraints and output sanitization:
  - compacts output to ~110 words
  - strips accidental markup
  - falls back when output is too short or invalid

### Shareable public report URL

- Deterministic report is persisted to Supabase and rendered at:
  - `**/report/[id]**`
- Public rendering is filtered by `is_public = true` and a public payload builder derives presentation insights.

### Lead capture (post-share)

- `LeadCaptureForm` posts to `**/api/leads**`
- Anti-spam:
  - hidden “honey” field
  - server-side cooldown (`COOLDOWN_MS = 8000`)
  - client-side retry cooldown and sessionStorage de-dupe for the current report session

## Architecture Summary

### High-level runtime pieces

- **Frontend**
  - `app/page.tsx` landing
  - `app/audit/page.tsx` audit input form
  - `app/results/page.tsx` results, share link UI, lead capture
  - `app/report/[id]/page.tsx` public report view
- **Backend (Next.js route handlers)**
  - `POST /api/reports` persists a public report in Supabase
  - `POST /api/summary` generates (or falls back) to the executive summary
  - `POST /api/leads` persists lead records
- **Deterministic audit engine (pure functions)**
  - `lib/audit/engine.ts` orchestrates rule outputs
  - `lib/audit/rules.ts` defines all business rules
  - `lib/audit/pricing.ts` provides pricing assumptions used for savings targets

### Deterministic audit engine flow

1. `AuditForm` validates user input.
2. `generateAuditReport(input)` runs pure rules:
  - builds context with tool spend aggregation
  - applies rules from `ALL_RULES` (pure functions)
  - de-dupes recommendations deterministically
  - selects at most one recommendation per toolId using precedence + savings tie-breaking
  - computes monthly/annual totals from selected recs

### AI summary isolation flow

1. Results page calls `POST /api/summary` after persistence.
2. `POST /api/summary`:
  - builds a prompt from deterministic inputs + top recommendations
  - attempts provider call (OpenAI by default)
  - sanitizes output and clamps word count
3. If provider output fails validation or provider keys are missing:
  - `fallbackSummary()` generates deterministic text based on the same audit report.

### Supabase persistence flow

1. When on `**/results`**, the app persists the deterministic report once:
  - `POST /api/reports` → inserts into `audit_reports` with `is_public = true`
2. The public report page:
  - loads the row with `is_public = true` (`getPublicAuditReportById`)
  - derives `insights` and renders.

### Public/private report separation

- Supabase table `public.audit_reports` stores both data and the `is_public` flag.
- Public rendering uses a query that explicitly filters:
  - `eq("is_public", true)`

## Tradeoffs / Engineering Decisions

1. **Deterministic engine vs. LLM-driven reasoning**
  - The main “savings math” is rule-based and computed deterministically in `lib/audit/engine.ts`.
  - The LLM is used only for narrative text (executive summary), not for the savings calculation itself.
2. **Local-first recommendations, server persistence**
  - Recommendations are generated in the browser from deterministic rules, then persisted server-side only when creating a shareable report.
  - This keeps the rules auditable and avoids paying LLM cost for the core output.
3. **AI summary fallback instead of hard failure**
  - If provider keys are missing or provider output is invalid, the system falls back to deterministic text (`fallbackSummary`).
  - This improves reliability and avoids “empty” results when LLM calls fail.
4. **RLS and service-role optionality**
  - Supabase RLS is enabled on `public.leads` and `public.audit_reports`.
  - The app attempts server-side lead inserts using a service-role key when configured, otherwise it falls back to anon insert (requires appropriate RLS policies).
5. **Shareable report idempotency via localStorage keys**
  - The results page avoids duplicate persistence POSTs using `persistAttemptedForKeyRef` and a deterministic localStorage-backed key (`buildPersistKey`).
  - This prevents rerender/StrictMode double-effect from creating multiple report rows.
6. **Anti-spam cooldown on lead submission**
  - The leads endpoint has a short cooldown (`8000ms`) and a hidden honey field.
  - Tradeoff: better protection vs. potential user friction during legitimate rapid retry.

## Deployment Notes

### 1) Supabase setup

1. Create the schema by running:
  - `supabase/schema.sql`
2. Ensure RLS policies for:
  - `public.audit_reports` insert (anon)
  - `public.leads` insert (anon) *or* configure server service role key for leads

### 2) Next.js environment variables

Set:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

Optionally set:

- `OPENAI_API_KEY` (or `ANTHROPIC_API_KEY`)
- `OPENAI_MODEL`, `ANTHROPIC_MODEL`

If leads must succeed regardless of anon policies:

- `SUPABASE_SERVICE_ROLE_KEY`

### 3) CI/build
In CI, the build step runs with non-sensitive environment values. Real Supabase connectivity depends on the correct environment variables in your deployment.
